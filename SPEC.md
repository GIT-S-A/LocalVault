# LocalVault SPEC

## §G Goal

One machine-local secret store per project: PS module (contract) + thin CLI + Claude skill. DPAPI-sealed local file, passphrase export/import between machines & people. Reads `SAAS-VAULT-1` exports & `secrets.local.clixml` vaults of existing copies w/o loss.

## §C Constraints

- C1: PowerShell 7.6+ (.NET 10), Windows only (DPAPI). C# `net10.0-windows`. ∀ `.ps1`: `Set-StrictMode -Version Latest`, `$ErrorActionPreference = 'Stop'`.
- C2: warnings = errors: C# `TreatWarningsAsErrors`, `Nullable enable`, `AnalysisLevel latest-recommended`; PSScriptAnalyzer clean. xUnit ∀ Core & Engine logic; Pester 6 ∀ cmdlet behaviour.
- C3: C# where logic lives, 3 layers. `LocalVault.Core` = shared contract, references nothing: store interfaces `IStore`/`IUnlockingStore`/`IStoreProvider`/`IStorePrompt` & their types, entry model (`VaultEntry`, `EntryName`, TOTP, SSH key info), exceptions, `StoreTypes`. `LocalVault.Engine` → Core: body, formats, crypto, vault file, store sync & registry, Hello, transfer, templates, SSH key files, git. `LocalVault.KeePass` = KeePass store over KeePassLib. `LocalVault.PowerShell` = binary cmdlets (contract): prompts (store prompts via `IStorePrompt` over host), SecureString, ShouldProcess, env; references Engine & store assemblies directly, picks provider by store `type`. Legacy clixml read needs PS deserializer → cmdlet layer. CLI = dispatch only.
- C4: vault in consuming project folder, gitignored. ⊥ `%LOCALAPPDATA%` for vault (KP registry, ⊥ secret, lives there).
- C5: one vault file may serve several scripts of one project.
- C6: SSH keys = `ssh-key` entries (§I.SSH keys), personal | shared, for SSH to hosts only; ⊥ git wiring (git over HTTPS). `__Ssh*` legacy import refused (V10, V139).
- C7: dev & tests ⊥ read real vault file; temp vaults only. `reference/` (local, ⊥ published) read-only, ⊥ imported at runtime.
- C8: formats evolve. ∀ published format (beta incl.) readable forever. Additive change (new field, new kind) → no bump (V20). Change old module can't rewrite safely → body `schema`+1. Change old module can't read (layout, sealing) → new magic `LOCALVAULT-<n+1>`. Crypto parameters in header → new KDF cost|cipher ⊥ new magic.
- C9: distribution = signed GitHub releases of `GIT-S-A/LocalVault` (assets `LocalVault.zip` = `install.ps1` + `LocalVault/<ModuleVersion>/` + `skills/localvault/`, `LocalVault.zip.sha256`, `install.ps1`), made locally by `tools/release.ps1`; ⊥ CI pipeline (V103), ⊥ package feed, betas ⊥ GitHub prerelease flag (`/releases/latest` must reach them). `install.ps1` 3 modes: next to `LocalVault/<ver>/` (unpacked release) → installs it; in a checkout (`src/`) → builds it (.NET 10 SDK; PlatyPS 1.0.3 from PSGallery if missing), dev only, unsigned; `-Latest` | `-Version <tag>` | neither → downloads release (V110). Destination per V94, side by side by `<ModuleVersion>`; Claude skill → `~\.claude\skills\localvault` when `~\.claude` ∃. Module folder carries `install.ps1`: `lv update [<tag>]` runs it w/ `-Latest` | `-Version <tag>`. Consumers pin w/ `#Requires -Modules`. Semver in manifest = tag; prerelease label = manifest `PSData.Prerelease` (letters & digits).
- C10: KeePass access = KeePassLib from KeePass 2 (GPL-2.0+), vendored unmodified in `vendor/KeePassLib`, built by `src/KeePassLib` (+ `Compat.cs` shims for APIs gone from .NET 10), referenced by `LocalVault.KeePass` only. Update only via `tools/update-keepasslib.ps1 -Version -Sha256` (SHA-256 from keepass.info + OpenPGP signature of key `D95044283EE948D911E8B606A4F762DC58C6F98E`). Vendor project: analyzers off, upstream obsolescence warnings listed in `NoWarn`, warnings=errors kept. ⊥ external KeePass tool.
- C11: help = PlatyPS 1.0 markdown in `docs/LocalVault/` (MS cmdlet-help style: synopsis verb-first, description opens "The X cmdlet ...", `Example n - title`, standard Force/WhatIf/Confirm text). Module page `LocalVault.md` = index; `about_LocalVault.md` = concepts. `docs/reference.md` = single page (concepts + ∀ command), generated by `tools/docs.ps1`, ⊥ hand-edited. Text = facts only: ⊥ rationale, ⊥ history, ⊥ advice. Build → `en-US/LocalVault.PowerShell.dll-Help.xml` + `about_LocalVault.help.txt`.

### Names

- name := `[scope/]key`; scope, key ∈ `[A-Za-z0-9._:@+-]+` (`@` `+` since beta6: email keys; older modules refuse such vaults), ≤ one `/`. Case-sensitive? → case-insensitive compare, case preserved (matches v1 hashtable).
- Dots part of key: `os.password` = unscoped key. `common/x`, `<deployment>/x` = scoped.
- Module ⊥ renames. v1 names (`OsPassword`, `GrafanaAdminPassword`, `LOKI_PUSH_TOKEN`) kept verbatim.

### Entry & body

```
entry := { name, kind: "secret"|"file"|"credential"|"required"|"hello", value: base64 ("" for required), previous?: base64, meta: { created: ISO-8601 UTC, path?: string, local?: true, required?: { note?: string, shape?: "credential"|"file"|"ssh-key", path?: string, hosts?: [string] }, kp?: { hash: hex, at: ISO-8601 UTC }, ssh?: { type: "ed25519"|"rsa"|"ecdsa", publicKey: string, hosts?: [string], agent?: true, replacedAt?: ISO-8601 UTC }, ref?: { store: hex, item: string, attachment?: string, title: string }, hello?: { kind: "secret"|"file"|"credential", hash: hex, vaultKey: hex16 } } }
body  := { schema: 5|6, exported?: ISO-8601 UTC, lastExported?: ISO-8601 UTC, entries: [entry...], kpRemoved?: [{ name, hash }], hello?: { keyId: hex, publicKey: b64, wrapped: b64, pad: "pkcs1" } }   UTF-8 JSON
```

- unknown body fields, entry fields, meta fields, kinds → kept verbatim on rewrite (V20).
- protection Hello is orthogonal to kind: an entry of kind secret | credential | file is either DPAPI only (vault file) or also sealed by Windows Hello. On disk a Hello entry has `kind: "hello"` & `meta.hello.kind` = its kind, so modules ≤ beta16 skip it in store sync (V20) and never send the sealed blob to a store (their `lv save` writes KeePass before the vault write that refuses schema 6). Module API & output: `Kind` = real kind, `IsHello` = protection. `value` = sealed blob (§I.Hello); credential fields (`user`, `urls`, `totp`) inside the seal; `meta.path` kept outside. `meta.hello.hash` = content hash (§I.KeePass) of plain entry, `vaultKey` = first 16 hex of SHA-256(vault public key) it was sealed under. Required declaration may carry `meta.required.hello: true`.
- local body only: `backup?: { id, destination, passphrase: b64, keyfile: b64, keyfileId: hex, lastBackup?, lastError? }`, left by releases ≤ beta14; read, ⊥ written. ⊥ in export (V33).

### Old backups

- module ⊥ writes backups (≥ beta15). Releases ≤ beta14 wrote `.lvbak` (envelope §I.Envelope mode `backup`) on every write when enabled.
- leftovers := own files in `backup.destination` (expanded; name `<yyyyMMddTHHmmssfffZ>[-<backup.id>].lvbak`, id = settings id) ∪ every backup-named file in default folder `%OneDrive%\LocalVault\<git root leaf>-<8 hex SHA-256(lowercase full vault path)>-<COMPUTERNAME>\` ∪ `backup` settings themselves.
- delete := files, then folders left empty (incl. `%OneDrive%\LocalVault`), then `backup` removed from body.
- restore: `Import-Vault -Source <x.lvbak>` (key from `backup` settings while kept) or `-KeyFile <path>` + passphrase.

### Stores

- store = place shared entries live beyond this PC. Types: `keepass` (target = `.kdbx` path). Target type from target: `.kdbx` → keepass; `<word>:` prefix (≥ 2 letters) → that type (`azkv:`, `keeper:`, `vault:` reserved) → error "not supported yet".
- common stores = this PC: `%LOCALAPPDATA%\LocalVault\stores.json` `{ schema: 1, default?: name, personal?: name, stores: [{ name, type, target, keyFile?, id?, unlockWith?, mirror? }] }`, per Windows account & machine, ⊥ secrets. Absent & `keepass.json` ∃ → converted once (`databases[].path` → `target`, type keepass); `keepass.json` left untouched.
- project stores = `localvault.json` `stores: [{ name, type?, target?, id?, mirror?, source? }]`; item w/o target = reference to the PC store of that name (⊥ keyFile: personal → common store w/ same target or id supplies it).
- `source: true` = reference source (V131): ⊥ written, ⊥ vault store; `id` required (filled from the PC store when added).
- name ∈ `[A-Za-z0-9._-]+`, case-insensitive unique per level. `%VAR%` in target & keyFile kept literal, expanded at use.

### Personal store

- personal value := entry w/ `meta.required` & value set (each person's own value of a declared entry).
- personal store := common store named by `stores.json` `personal` (≤ 1, PC only, ⊥ project level, ⊥ default). Absent → personal values stay on this PC.
- holds personal values, same group layout as §I.KeePass (per project & vault); entry = value as kind secret|credential|file, ⊥ declaration. Personal values ⊥ sent to any other store.
- personal file value (e.g. SSH private key): file entry w/ `meta.required`; stored path may be `~/<rel>` = under `%USERPROFILE%` (V118); `~/` paths ⊥ for other entries, except shared `ssh-key` entries (V122). Declaration shape `file` (`lv require <name> -StoredPath <path>`) carries a default path (`meta.required.path`, KeePass `LocalVault.RequiredPath`).
- personal store may also be a mirror (`-Mirror`, V95) → copy of shared entries + personal values in the same groups.
- personal store id = id of the vault's primary (same DB) → console: warning (personal values readable by everyone w/ access to that DB) + one question per run, default no; yes → declaration & value in one entry (`LocalVault.Kind` = required, Notes = note, value fields set); no | non-interactive → personal values ⊥ written there, warning.
- sync state per DB id (V79): personal value's base in `meta.kp."personal:<db id>"` (content hash of the value), removal markers `db: "personal:<db id>"`; ⊥ mixed w/ the declaration's base, even in the same DB.
- reference (§I.References): personal value may point to an item in any store defined on this PC; module ⊥ writes outside `LocalVault/` groups.

### References

- reference := store entry in vault group pointing to an item instead of holding the value; resolved by module (⊥ KeePass `{REF:}` written).
- store entry: title = entry name, `LocalVault.Kind` = `reference`, `LocalVault.RefShape` = secret|credential|file|ssh-key, `LocalVault.Ref` = `<store id>/<item id>[/<attachment>]`, `LocalVault.Path` (file, ssh-key), ssh fields (§I.SSH keys), personal → `LocalVault.Personal`; ⊥ value fields.
- store id = database id (§I.KeePass); item id = KeePass entry UUID (32 hex).
- target read: secret → Password; credential → same fields as a credential entry (user, password, URLs, TOTP fields); file → attachment; ssh-key → attachment + public key parsed (V131). `{REF:…@I:…}` inside target → resolved within its DB, chain ≤ 8.
- allowed target: personal value → any store defined on this PC; shared → vault's store | project store w/ `source` & `id`; never personal store, never a store named by any `unlockWith`.

### SSH keys

- ssh-key entry := file entry w/ `meta.ssh`; personal (declaration shape `ssh-key`, value in personal store) | shared (project store). For SSH to hosts; ⊥ git.
- value = private key (OpenSSH format) | public key when `meta.ssh.agent` (private key stays in the agent). `meta.ssh.publicKey` = OpenSSH public key line (⊥ secret) → `.pub` files & fingerprint (`SHA256:` OpenSSH form) w/o process call. `previous` = replaced key while not retired (V129).
- hosts := `[user@]host[:port]` list, ⊥ secret; personal → `meta.required.hosts` (shared w/ declaration); shared → `meta.ssh.hosts`.
- `<repo>` := last segment of `git remote get-url origin` w/o `.git`; ⊥ origin → git root leaf. Fixed at creation in the stored path → same path in every clone & for every teammate.
- file := entry name, `/` → `.`, `:` → `_`; two entries → same file → second refused.
- files: `~/.ssh/<repo>/<file>`, `<file>.pub`, while `previous`: `<file>.old` (old private key) | `<file>.old.pub` (old agent key = public key); agent key → `<file>.pub` only. ACL per V119. Stored path rule V140.
- marker `~/.ssh/<repo>/.localvault` (⊥ secret, UTF-8 JSON) `{ schema: 1, origin, keys: { <file>: { hash: hex SHA-256 of file bytes, writtenAt: ISO-8601 UTC, writtenBy: <vault path>, users: [<vault path>...] } } }`; lock `.localvault.lock` (V3 rules).
- `~/.ssh/<repo>/lv.config` (V134): one block per host of each entry.
- KeePass: attachment `<file>` (value), `<file>.old` (previous); `LocalVault.SshType`, `LocalVault.SshPublicKey`, `LocalVault.SshHosts` (one per line), `LocalVault.SshAgent` = `true`, `LocalVault.ReplacedAt`; personal value → `LocalVault.Personal` = `true` (V142). Content hash of ssh-key entry covers value, previous & hosts; declaration hash (V118) covers hosts.
- orphan := key in a marker whose users' vault files all ⊥ exist (users ∅ included: writes drop dead users per V126) (V133).

### Hello

- hello entry := entry w/ protection Hello (on disk kind `hello`); kinds secret | credential | file; ⊥ ssh-key, ⊥ required w/o value. Opt-in per entry; other entries plain (vault file DPAPI-sealed as before, hello layer inside). Protection moves both ways (`-Protection Hello|Dpapi`, `lv mark hello|nohello`) w/o changing kind, value, `created`, local flag, KeePass bases or content hash.
- Hello key := RSA-2048 in `Microsoft Passport Key Storage Provider` (`MS_NGC_KEY_STORAGE_PROVIDER`), one per Windows user, name `<user SID>//LocalVault/Hello/LocalVault-Hello`; `NCRYPT_NGC_CACHE_TYPE_PROPERTY` = `NCRYPT_NGC_CACHE_TYPE_PROPERTY_AUTH_MANDATORY_FLAG` (every decrypt prompts); export policy 0 (non-exportable). Created on first seal (one Hello prompt). `keyId` = hex SHA-256 of its `BCRYPT_RSAPUBLIC_BLOB`. Hardware := key property `NgcKeyImplType` has `NCRYPT_IMPL_HARDWARE_FLAG` (0x1) (TPM; 0x20 = virtual isolation); bit absent | property unreadable → software key, reported (V147). Key property `Impl Type` ⊥ supported; provider reports 3.
- vault key := P-256 key pair per vault, made w/o prompt when first hello entry is sealed; body `hello.publicKey` = SubjectPublicKeyInfo; `hello.wrapped` = private scalar (32 B) encrypted by Hello key, RSA PKCS#1 v1.5 (`pad`; NGC KSP refuses OAEP SHA-1 & SHA-256 with `NTE_INVALID_PARAMETER`; decrypt gated by a Hello gesture per call); `hello.keyId` = Hello key that wrapped it.
- sealed blob (base64 in `value`): `0x01` ‖ ephemeral P-256 public point (65 B, uncompressed) ‖ nonce (12 B) ‖ tag (16 B) ‖ ciphertext. Key = HKDF-SHA256(ECDH(ephemeral, vault key), salt = keyId bytes, info `LOCALVAULT hello`, 32 B); AES-256-GCM; AAD = UTF-8 `name` ‖ 0x00 ‖ sealed kind ‖ 0x00 ‖ keyId (lowercase hex). Plain = UTF-8 JSON `{ value: b64, user?, urls?, totp? }`.
- seal: vault public key only → ⊥ prompt. unseal: one Hello decrypt of `hello.wrapped` per command → vault private key → entries; scalar & plain buffers zeroed after the command (V145).
- Hello state := `ready` | `software` (key ∃, ⊥ TPM) | `none` (key ⊥ created) | `unavailable` (Hello ⊥ set up, remote session, ⊥ interactive, provider error) | `key changed` (vault `keyId` ≠ key's). Entry Missing w/o prompt: state ≠ ready | vault `keyId` ≠ key's | `meta.hello.vaultKey` ≠ current vault key.
- KeePass: hello entry stored plain as its kind + custom string `LocalVault.Hello` = `true`; declaration → `LocalVault.RequiredHello` = `true`. Flag ⊥ in content hash.
- interface `IHelloKey` (Core): `State`, `UnavailableReason`, `IsHardware`, `KeyId`, `PublicKey`, `Create(message)`, `Decrypt(wrapped, message)`; `HelloKeys.Current` = Windows key; tests set internal `HelloKeys.Override` (in-process only, ⊥ setting on disk) to a software RSA key.

### KeePass

- KeePass = team store of shared entries, readable w/o LocalVault. Entry ``shared`` by default; ``meta.local: true`` → ⊥ sent, ⊥ touched by load.
- unlock: master password prompted per command (hidden; empty → no password key); keyfile from registry. ⊥ cached, ⊥ env var. Composite key bytes zeroed after open.
- KeePass store: keyFile & unlockWith from common store (same id | same expanded target).
- `-Store` = store name: project store > common store.
- group := `LocalVault/<git root leaf>[/<dir segment>...][/<file name>]`: dir segments = vault dir relative to git root; file name only when ≠ `secrets.local.lv`. ⊥ git root → `LocalVault/<vault dir leaf>[/<file name>]`. Missing groups created.
- entry: title = full vault name (`key` | `scope/key`); custom string `LocalVault.Kind` = `secret`|`file`. secret → Password (protected). file → attachment named leaf of path + custom string `LocalVault.Path` = stored path. Entry w/o `LocalVault.Kind` → secret from Password (added by hand in KeePass). Only direct entries of vault group read; subgroups = other vaults.
- guide entries (V109): `LocalVault/` holds `Install instructions for localVault` (kind `install`: Notes = README install line); `LocalVault/<git root leaf>/` holds `Repository origin` (kind `origin`: URL = `git remote get-url origin` ⊥ credentials, Notes = `git clone <url> <leaf>`, `cd <leaf>`, `lv load`, pointer to install entry). Read ⊥ guide entries (⊥ item, ⊥ skipped).
- content hash := hex SHA-256(kind ‖ 0x00 ‖ path ‖ 0x00 ‖ value bytes). `meta.kp.hash` = content hash when last equal in vault & KeePass (base).
- edit of KeePass entry → previous version kept in entry history; delete → KeePass recycle bin when enabled.
- save → database changed on disk since open → reopened & merged (KeePass synchronize) before write.
- database id := hex UUID of root group (same in every copy of a .kdbx); registry caches it per registered DB after first open. ∀ save → also in KDBX 4 outer header `PublicCustomData` `LocalVault.DatabaseId` (unencrypted, ⊥ secret) → readable w/o password (V155).
- project file `<git root>/localvault.json` (committed, ⊥ secret), schema 2: `{ schema: 2, default?: { store, id? }, stores: [...], vaults: [{ path, store?, id? }] }`; path repo-relative `/`. Schema 1 (`stores: [{ role: "primary", type, id, label? }]`, `vaults: ["<path>"]`) read: primary → `default { store: label, id }`; rewritten as schema 2 on next write. Vault item = string → `{ path }`. Store item w/o `name` ignored. Unknown fields kept. ∀ write of a vault in a repo → `{ path }` added to `vaults` (person told to commit).
- vault store := `-Store` > vault item `store`/`id` > project `default` > common default store > sole common store. Reference (name, id?) resolved: project store by name > common store by id > common store by name. Opened DB id ≠ reference id → error, nothing written. Unresolved → "<vault> uses store '<name>', which isn't defined on this PC" (repo-wide save/load: that vault skipped, others continue; all skipped → error).
- unlock: common store w/ `unlockWith: <store>` → unlocker opened first (its own unlocker first; chain ≤ 8), master read from unlocker's `AutoOpen` group (KeePassXC/KeeAutoExec convention): URL = DB path (abs | relative to unlocker | `{DB_DIR}` | `kdbx://` | `file:`), Password = DB master, UserName = keyfile path, `IfDevice` = comma list, `!` excludes; LocalVault adds `LocalVault.DatabaseId`; match by id, else path. No match → DB master asked; interactive → offer to keep it in unlocker's AutoOpen. No `unlockWith` → master asked. Unlocker opened only when a store naming it is needed.
- `meta.kp` := `{ <dbId>: { hash, at } }` (beta4 `{ hash, at }` = base of whichever DB next syncs, then rewritten keyed); `kpRemoved` items carry `db?`.- KeePass 2 w/ same DB open → its next save may offer overwrite of external change; module tells person to reload DB there.


- secret value = base64(UTF-8 text). file value = base64(raw bytes).
- `meta.created` = time value last set.
- `meta.path` (file only) = path relative to vault dir, `/` separators; ⊥ absolute, ⊥ `..` escaping vault dir.

### Envelope `LOCALVAULT-2`

```
line 1  magic   LOCALVAULT-2
line 2  mode    local | export | backup
line 3  params  key=value;key=value   (keys sorted, ASCII)
line 4+ data    base64, one value per line

local   seal=dpapi-user                                                               / <b64 sealed body>
export  cipher=aes-256-gcm;iterations=210000;kdf=pbkdf2-sha256                        / <b64 salt16> / <b64 nonce12> / <b64 tag16> / <b64 cipher>
backup  cipher=aes-256-gcm;iterations=210000;kdf=pbkdf2-sha256-hkdf-keyfile;keyfile=<hex id>  / same 4 lines
```

- AAD (export, backup) = UTF-8 of lines 1–3 joined by `\n` → header tamper → fail.
- kdf `pbkdf2-sha256`: PBKDF2-SHA256, `iterations`, 32 B key. `pbkdf2-sha256-hkdf-keyfile`: key = HKDF-SHA256(PBKDF2 key ‖ keyfile, salt, info `LOCALVAULT-2 backup`). cipher `aes-256-gcm`: 16 B tag.
- reader: `iterations` ∈ [100000, 10000000]; unknown mode, key or value → V51 error. Writer: current params only.
- wrong keyfile → error naming expected keyfile id.
- passphrase ≥ 12 chars; interactive → asked twice.

### `SAAS-VAULT-1` (read only)

```
SAAS-VAULT-1 / <b64 salt16> / <b64 nonce12> / <b64 tag16> / <b64 cipher>     no AAD
body := { "<name>": "<plain string>", ... }
```

Map: plain name → secret; `__File:x` → file `x`, `meta.path = x`; `__SshPrivateKey`, `__SshPublicKey` → refused, reported, rest proceeds; other `__*` → refused, reported.
Body parsed w/ case-sensitive keys (`ConvertFrom-Json -AsHashtable` ?); case-only clash → V28.

### Cmdlets (all take `-Path`)


## §V Invariants

V1: ∀ secret value → ⊥ on command line, ⊥ in output/verbose/debug/log/error streams, ⊥ outside sealed files. Input via SecureString, stdin or hidden prompt.
V2: ∀ write → read-modify-write of existing entries; entries not named by write unchanged. ⊥ rebuild from caller state.
V3: ∀ write → under exclusive `<vault>.lock` (`FileShare.None`, retry ≤ 10 s then error); body written to `<vault>.tmp-<guid>` then `File.Replace` (or `File.Move` if new). Crash mid-write → old vault intact.
V4: ∀ name → validated vs §I.Names before any read or write; invalid → error, nothing written.
V5: `Get-VaultEntryList` & `lv list` → name, kind, created/age, credential user name only; ⊥ value.
V6: import → all conflicts resolved before single write. identical → silent; missing → added; different → listed, person picks, default none. `-Replace`/`-ReplaceAll` skip question.
V7: import non-interactive (input redirected | `-NonInteractive`) & unresolved conflicts → error (CLI exit 2), nothing written.
V8: wrong passphrase | tampered export | tampered header → error, vault unchanged.
V9: export passphrase < 12 chars | two entries differ → error, nothing written.
